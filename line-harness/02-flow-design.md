# 02. 配信設計 — 何をどの機能に載せるか

`presales-education-video/` の配信設計（予約直後は上げっぱなし／前日は落として上げて決断へ）を、
L Harness の機能に**そのまま**載せるための設計。文面の意図は変えない。変えたのは差し込み変数と送り方だけ。

---

## 全体タイムライン

```
体質診断VSL（LP）
  │  友だち追加（LIFF/OAuth 経由。流入元 ref を自動記録）
  ▼
[S0] 友だち追加あいさつ ─── シナリオ `診断会_友だち追加`（friend_add）
  │  予約ページ https://liff.line.me/{LIFF}?page=book で日時を選ぶ
  ▼
予約リクエスト（status: requested）
  │  L Harness 標準通知「予約リクエストを受け付けました」
  │  メニューの自動タグ → `診断会_予約申込`
  │
  │  sync-bookings.mjs（5分おき）が自動承認 → status: confirmed
  │  L Harness 標準通知「予約が確定しました（メニュー／担当／日時）」
  │  Googleカレンダーに予定作成 ／ タグ `診断会_予約確定`
  ▼
[S1] 予約直後 3通 ──────── シナリオ `診断会_予約直後`（確定から最大5分後）
  │   お礼＋日程 → 動画（2:34・褒め） → 当日までの過ごし方
  │
  │   …（数日）…
  ▼
[S2] 前日 19:00 3通 ─────── シナリオ `診断会_前日19時`（absolute_time モード）
  │   前振り → 動画（3:00・教育） → 宿題の念押し
  ▼
[S3] 当日 2時間前 1通 ───── シナリオ `診断会_当日2時間前`
  │   Zoom URL・持ち物・担当者名
  ▼
個別体質診断会（Zoom 60分）
```

---

## 判断1：3セットは「シナリオ」に載せ、登録タイミングをスクリプトが決める

L Harness には日付基準で送る仕組みが2つある。どちらもそのままでは足りない。

| 仕組み | できること | この案件で足りないこと |
|---|---|---|
| **予約管理の標準リマインド** | 確定時に「前日（24時間前）」「2時間前」を自動予約 | 文面が固定（「明日のご予約のお知らせです」）で動画も宿題も入らない。24時間前＝前日の同時刻なので 19:00 に揃わない |
| **リマインダー機能**（`/api/reminders`） | 「対象日時 ± n分」で任意の文面を配信 | `{{name}}` などの変数展開が**効かない**（`reminder-delivery.ts` は変数を展開しない）。文面は全通「〇〇さん」で始まるので致命的 |
| **シナリオ** | 変数展開あり・Flex 可・絶対時刻モード（`absolute_time`）あり | 「予約日時の前日」を起点にできない（起点は登録時刻） |

→ **シナリオを使い、「いつ登録するか」を `sync-bookings.mjs` が予約データから決める。**

- `診断会_予約直後`：確定を検知したら即登録（relative モード、0分/0分/1分）
- `診断会_前日19時`：前日の日付になったら登録（absolute_time モード、当日 19:00 / 19:00 / 19:01）。
  登録が 19:00 を過ぎていた場合は即時配信、22:00 を過ぎていたら送らない
- `診断会_当日2時間前`：開始2時間前を過ぎたら登録（relative、0分）。開始時刻を過ぎていたら送らない

この方式の弱点は「スクリプトが止まると S1〜S3 が止まる」こと。対策は [03-operations.md](03-operations.md) §3（実行の監視）。

### 標準リマインドとの二重送信について

予約確定時に L Harness が標準の「24時間前」「2時間前」通知を自動予約する。API からは止められない。

| 選択肢 | 結果 |
|---|---|
| **A. そのまま**（初期設定） | 前日：24時間前に短い標準通知 ＋ 19:00 に3通。当日：2時間前に標準通知と S3 がほぼ同時に届く。内容は矛盾しない（標準通知はメニュー／担当／日時のみ） |
| **B. D1 を直接更新して止める** | `sync-bookings.mjs` に `LINE_HARNESS_D1_NAME` を設定すると、`wrangler d1 execute` で未送信の標準リマインドを `cancelled` にする。wrangler にログイン済みのマシンで動かす必要がある |

まずは A で運用開始し、当日2時間前の2通同時が気になれば B に切り替える。

## 判断2：予約直後は「自動タグ」ではなく「確定検知」で送る

メニューには「予約申込時に自動付与するタグ」があり、そのタグをトリガーにシナリオを即発火できる。
しかし LIFF からの予約は **`requested`（承認待ち）** で入る。ここで「日程が確定しました！」を送ると、
標準通知の「お店からの返信をお待ちください」と矛盾する。

→ `sync-bookings.mjs` が `requested` を **自動承認**してから `診断会_予約直後` に登録する。
承認まで最大5分（実行間隔）。予約直後の不安を潰す目的からは「5分以内に確定通知＋お礼動画」で十分と判断。
担当者が目視で承認したい場合は `config/funnel.json` の `autoApprove` を `false` にする（管理画面「予約管理 → リクエスト」で承認した瞬間に S1 が走る）。

---

## 判断3：日程変更は「キャンセル → 再予約」、2回目は動画を送らない

L Harness に「予約の日時変更」は無い。運用は **管理画面でキャンセル → 友だちに再予約してもらう**（または管理画面から代理予約）。

再予約が確定したとき、同じ友だちにもう一度 S1 の動画を送ると不自然なので、
2回目以降は `診断会_日程変更`（短い確定文1通）を送る。S2・S3 は新しい日程で改めて送る（宿題の再送、という元設計の方針どおり）。

判定は友だちメタデータ `diag_thanks_sent_for`（S1 を送った予約ID）で行う。

## 差し込み変数（友だちメタデータ）

`sync-bookings.mjs` が確定予約ごとに友だちの `metadata` へ書き込む。シナリオ本文からは `{{metadata.KEY}}` で参照する。

| キー | 例 | 由来 |
|---|---|---|
| `diag_booking_id` | `3f2a…` | bookings.id |
| `diag_date` | `9月20日（土）` | starts_at を JST に変換 |
| `diag_time` | `14:00` | 同上 |
| `diag_staff` | `山田` | staff.display_name |
| `diag_meeting_url` | `https://zoom.us/j/…` | `config/assets.json` の `staffMeetingUrls[担当者名]`（無ければ `defaultMeetingUrl`） |
| `diag_thanks_sent_for` | 予約ID | S1（または日程変更）を送った予約 |
| `diag_prevday_sent_for` | 予約ID | S2 を送った予約（`skipped:` 付きは送らなかった記録） |
| `diag_sameday_sent_for` | 予約ID | S3 を送った予約 |

`{{name}}` は LINE の表示名。ニックネームの人も多いので、文面は「{{name}}さん」で違和感が出ない書き方にしてある。

**Zoom URL について**：L Harness の Googleカレンダー連携は Google Meet を作れるが、この案件は Zoom 運用なので
担当者ごとの固定 Zoom URL（パーソナルミーティングID）を `assets.json` に置く方式にした。
Meet に切り替える場合は `defaultMeetingUrl` を空にし、当日文面から URL を外して標準通知に任せる。

## 動画の送り方

シナリオの `messageType` は `text` / `image` / `flex` のみで、LINE の video メッセージ型は無い。
**Flex Message の hero ブロックに `video`** を置くと LINE アプリ内でインライン再生される（LINE 10.x 以降）。

- 必要：mp4 の HTTPS URL、サムネイル画像 URL、縦横比（9:16 想定）
- 再生できない環境ではサムネイル（`altContent`）が出る
- 通知欄に出る文字（altText）は Flex 本文の最初のテキストから自動で取られる

mp4 が無い間は `assets.json` に `linkUrl` だけ書く。`apply.mjs` が「テキスト＋URL」に切り替え、
L Harness の自動トラッキング機能で URL がボタン付き Flex になり、**誰がタップしたか**が記録される。

## タグ設計

| タグ | 付与タイミング | 使い道 |
|---|---|---|
| `診断会_予約申込` | 予約リクエスト時（メニューの自動タグ） | 申込したが未確定・キャンセルの人を拾う |
| `診断会_予約確定` | 自動承認時（スクリプト） | 確定者への一斉連絡、着座率の分母 |

セグメント配信の例：「`診断会_予約申込` あり かつ `診断会_予約確定` なし」＝ 承認されずに流れた人。

## 制約・注意（実装から確認済み）

- シナリオの配信は Cron（1分おき）。`delay 0` でも最大1分の遅れがある。「19:00 ちょうど」ではなく「19:00〜19:06」（ステルス用の ±5分ジッター込み）
- 同じ友だちを同じシナリオに**同時に**2回登録はできない（前回分が `completed` になれば再登録できる）。3通セットは1〜2分で完了するので、実運用ではまず衝突しない。衝突した場合スクリプトは次回実行で再試行する
- Cloudflare 無料プランは Cron 1回あたり送信 40 通まで。1日の診断会が 40 件を超える規模になったら有料プラン
- LINE 表示名が空の人は `{{name}}` が空文字になる。文面は「さん」だけ残っても読めるように句読点を調整済み
- 予約ページ（LIFF）は「今から60分以内」の枠を出さない。当日の飛び込み予約は管理画面から代理予約する
